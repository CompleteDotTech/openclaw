# Dictation data policy qualification

This is preparatory implementation for [issue #205852](https://github.com/openclaw/openclaw/issues/205852), planning item P04. It is not an accepted or fully qualified local-only product. The issue stays open until every criterion below is met. The configuration, transport matrix, consumer scope, and rollback contract need the Talk and relevant security/update owners' acceptance.

## Owner decision requested

**Status: proposed, awaiting Talk and relevant security/update owners.** [ClawSweeper's durable review](https://github.com/openclaw/openclaw/issues/205852#issuecomment-7186749703) asks whether Talk should support an opt-in speech-data restriction and which adapters, destinations, and request-lifetime semantics it would cover. It establishes no existing strict-local security bypass. Ordinary automatic streaming fallback when a file model is unavailable is intentional and must remain unchanged when no restriction applies.

For the candidate adapter, the existing fork allows a literal-IP endpoint with HTTP only on loopback and HTTPS otherwise. Its constrained route rejects hostnames, redirects, proxies, URL credentials/query/fragment, credential-profile overrides, custom headers, and opaque transport hooks. It uses one configured model, a bounded content-free readiness probe, and one transcription attempt; no automatic install, model download, retry, or alternate provider is proposed. These are **candidate matrix choices**, not an approved adapter contract or evidence that an inference server cannot make secondary connections. Owners must name and qualify the actual runtime/version/model/topology before granting any locality claim.

The smaller alternative is readiness and destination disclosure without a strict speech-data guarantee. Whole-Gateway offline enforcement, every adapter, native/device-local engines, installers, global TTS integration, and automatic refinement remain deferred. Missing P02/P03/M11 contracts cannot be treated as accepted dependencies. Do not silently reduce the original acceptance criteria to make this narrower proposal appear complete.

### Request admission versus cancellation

The [repository guidance](https://github.com/CompleteDotTech/openclaw/blob/206baecd1cb5397d8a2e4df8e1c602272b1d4226/AGENTS.md) defaults to checking authority once when work starts. Removal, reload, and revocation apply to the next request; admitted work may finish. Queued, retried, and replayed work enters the same admission as new work. The proposed recording/finalization unit above applies that default to this flow, but is not an accepted Talk contract.

The existing fork implements stronger experimental behavior: `speechPolicyRevision()` fingerprints policy, media, provider, voice, plugin, and proxy inputs; `captureTalkSpeechDataAuthority()` rechecks that revision; and the transcription relay subscribes to config publication and can abort its owned session. The dispatch matrix and historical tests below describe those checks. They do **not** mean admission-once semantics have been implemented or that config-driven mid-session revocation has been accepted.

If stronger revocation is requested, the decision must identify the concrete failure being prevented, its likelihood, the user-visible outcome, and the cost of repeated checks, hashing, and config subscriptions. The current review establishes no existing bypass or measured incidence that settles that tradeoff. Confirm whether a configuration change should prevent only the next recording or also stop an admitted recording, upload, or result publication. Do not implement both interpretations under one promise.

That policy decision is separate from explicit Cancel/discard, disconnect, request or session replacement, buffer ownership, and stale-result suppression. Preserve the existing abort/close and liveness checks for those real lifecycle events, together with applicable transport and side-effect admission rules. Do not remove every `assertCurrent` call merely because part of it checks a policy revision. Cancel can stop further owned work and discard a result; it cannot recall bytes already transmitted.

### Evidence needed before the drafts advance

Acceptance requires the approved adapter matrix to be exercised at actual dispatch, not inferred from provider names or catalog fields. Use a named runtime/version/model and topology with the actual served Control UI and Gateway; observe permitted and denied connection attempts, hint payloads, failure/fallback, cancellation, and result placement. Record the served build identity and accessibility behavior. Resolve the supported stable version at execution time and prove update/rollback preservation against it. A content-free model probe, modeled fixtures, generated protocol checks, and an older-version schema rejection do not provide that proof.

The six unresolved boundaries remain visible: catalog selection is not atomically bound to automatic `chat.send`; global `tts.speak` lacks speech-origin policy; an entered opaque provider controls its internal networking; stopping an already-active native/direct connection is unproved; a trusted server may forward data; and an older Doctor may strip the restriction. The detailed ledger retains all twelve acceptance criteria and their incomplete status.

## Enforcement boundary and initial matrix

The proposed restriction applies to the owned raw composer dictation path. It is not a firewall for the Gateway process, an attestation about a remote server, or permission to send an automatically refined transcript elsewhere. A trusted server may itself forward content; the operator is choosing that server explicitly.

| Route                                                                     | Candidate behavior                                                                                                                                                   | Qualification                                                                                                                    |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Device-local inference                                                    | Unavailable; no adapter proves that inference runs on the microphone device                                                                                          | Native/runtime/model and device-identity evidence missing                                                                        |
| Explicit no-auth OpenAI-compatible batch endpoint at a literal IP         | One selected existing media model, exact base URL, bounded content-free model probe and one guarded WAV request; HTTP only for loopback, HTTPS for other literal IPs | Modeled transport fixtures pass; actual socket fixtures skipped on the proxied host; real server/model version still unqualified |
| Gateway-host loopback endpoint                                            | Labeled trusted endpoint on the Gateway host                                                                                                                         | Never labeled microphone-device local                                                                                            |
| Hostname endpoint, redirect, proxy, credentialed/custom request transport | Unavailable in the initial restricted matrix                                                                                                                         | No implicit downgrade or transport substitution                                                                                  |
| Arbitrary CLI, native label, opaque plugin or fallback provider           | Unavailable under restriction                                                                                                                                        | No branding-based local claim or runtime model download                                                                          |
| Absent policy or explicit external mode                                   | Existing provider behavior                                                                                                                                           | Preserve voice notes and unrelated provider configuration                                                                        |
| Split Talk, Live Talk, remote refinement under restriction                | Unavailable until their automatic transcript/context dispatch is covered                                                                                             | Raw transcription must remain separate from optional refinement                                                                  |

The proposed `talk.speechDataPolicy` is optional. A missing value is distinct from an explicit restriction. The restricted endpoint consumes existing media model configuration; it adds no model registry, engine, installer, or credential resolver. Every shared media entry needs explicit capability tags; ambiguous inferred capabilities fail unavailable rather than silently skipping a possible selected provider. Existing plugin enable/deny policy is respected. Unsupported combinations fail before plugin/auth preparation. The existing compatible-audio multipart owner performs the constrained request.

## Current ownership gaps

These are implementation and integration gaps, not hardware-only qualifications:

- Split Talk checks the catalog before automatic `chat.send`, but the subsequent RPC is not atomically bound to that policy. It can also use global `tts.speak`, which has no speech-origin policy marker. Neither guard establishes a complete automatic derived-data guarantee.
- Host Talk TTS rechecks permission before preparation, after asynchronous preparation before synthesis, before fallback, and before publishing a result. An already-entered opaque provider controls its internal networking and is not forcibly aborted by those checks.
- Existing native/direct peer transports are outside the raw browser dictation owner. New managed entry points are denied, but a previously active native/direct connection is not proven to stop immediately.
- A trusted endpoint is an operator-selected recipient, not an attestation that the server never makes secondary connections. The Gateway constrains its own request only.

Consequently AC04, AC06 and AC07 remain partial even if raw-route fixtures pass. Device-local stays unavailable. No fully local-only product claim or rollout is authorized by this candidate.

## Migration and rollback boundary

Ordinary existing configurations remain unchanged when the option is absent; credentials are not deleted. Candidate normalization retains the authored restriction, including unsupported raw policy fields until validation rejects them.

Older normal config validation rejects the unknown key, but that is not sufficient rollback safety. Older Doctor normalization reconstructs known Talk fields, and its unknown-key repair can remove `talk.speechDataPolicy` before startup. This candidate cannot change historical binaries. Until an accepted update-owner solution and actual supported-version rollback test establish preservation, rollback qualification remains blocked. Do not advertise a fail-closed downgrade guarantee or recommend running an older Doctor against restricted state.
